El archivo "docker-compose.yml" es el director de la infraestructura. Se encarga de descargar las imágenes, levantar los contenedores de Docker, abrir los puertos necesarios y conectar los volúmenes de datos locales con el interior de los contenedores.

El archivo con la estructura final del proyecto tiene la siguiente forma:

``` docker-compose.yml
services:
  # 1. BASE DE DATOS (PostgreSQL)
  db:
    image: postgres:15-alpine
    container_name: prado_matrix_db
    restart: always
    environment:
      POSTGRES_USER: ******
      POSTGRES_PASSWORD: ******
      POSTGRES_DB: ******
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5433:5432"

  # 2. BACKEND (Python + FastAPI)
  backend:
    build: ./backend
    container_name: prado_matrix_backend
    restart: always
    ports:
      - "8000:8000"
    volumes:
      - ./backend:/app
    env_file:
      - .env
    depends_on:
      - db

  # 3. FRONTEND (React + Vite)
  frontend:
    build: ./frontend
    container_name: prado_matrix_frontend
    restart: always
    ports:
      - "5173:5173"
    volumes:
      - ./frontend:/app
      - /app/node_modules
    env_file:
      - .env
    depends_on:
      - backend

volumes:
  postgres_data:
```

## Explicación de la Configuración
---
La infraestructura se divide en tres servicios principales y un volumen:
### 1. Servicio: `db` (Base de Datos PostgreSQL)

Es la base de datos relacional encargada de almacenarla configuración de las salas, usuarios, mensajes programados etc.

- **image:** Utilizamos `postgres:15-alpine`, una versión oficial muy ligera basada en Alpine Linux.
- **container_name:** Simplemente especifica el nombre del contenedor.
- **restart: always:** Nos garantiza que si la máquina se reiniciase, el servicio se vuelva a arrancar automáticamente.
- **environment:** Para definir las variables iniciales de entorno con las que se construirá la base de datos (usuario, nombre y contraseña)
- **volumes:** Carga la información de la carpeta `/var/lib/postgresql/data` con el directorio `postgres_data` dentro del propio contenedor. 
- **ports:** Mapeamos el puerto interno `5432` al puerto externo `5433` de nuestra máquina. Lo ponemos en este puerto para evitar conflictos si ya hubiese otro PostgreSQL local-

### 2. Servicio: `backend` (Python + FastAPI)

- **build:** En vez de descargar una imagen, le indicamos a Docker que construya la suya propia leyendo del archivo `Dockerfile` que hay dentro de la carpeta backend.
- **container_name:** Para el nombre del contenedor.
- **restart: always:** Lo mismo que para la base de datos, arranque automático.
- **ports:** Exponemos el puerto `8000`, que es donde escucha el servidor uvicorn de FastAPI.
- **volumes:** Mapeamos la carpeta local `./backend` a la carpeta `/app` del contenedor. Esto permite la recarga en caliente, si modificas el código de Python los cambios se aplican al instante.
- **env_file:** Para inyectar el archivo `.env` y así definir contraseñar y variables sensibles sin que se queden expuestas en el código.
- **depends_on:** Le dice a Docker que no arranque el backend hasta que el contenedor db esté completamente levantado.

### 3. Servicio: `frontend` (React + Vite)

- **build:** Le indicamos que construya su imagen usando el `Dockerfile` de la carpeta frontend.
- **container_name:** Para el nombre del contenedor
- **ports:** Exponemos el puerto `5173`, que es el puerto por defecto que utiliza Vite.
- **volumes:** Aquí hacemos dos mapeos:
    - **./frontend:/app**: Mapeo para que los componentes de React se puedan modificar en caliente.
    - **/app/node_modules**: Sirve como protección para evitar que la carpeta `node_modules` de nuestra máquina local sobrescriba la carpeta interna del contenedor y provoque fallos de dependencias.
- **env_file:** Carga el .env para que React sepa a que URL hacer las peticiones de la API.
- **depeds_on:** Le dice a Docker que no arranque el frontend hasta que el backend esté completamente levantado.
