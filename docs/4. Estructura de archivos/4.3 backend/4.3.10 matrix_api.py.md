Este archivo ubicado en `services/matrix_api.py` es uno de los principales de nuestra aplicación. Aquí se definen todas las peticiones HTTP dirigidas a la API de matrix. Estas funciones son las que se llamarán posteriormente desde los endpoints propios de la aplicación.

Para realizar esto el archivo interactúa con dos tipos de peticiones distintas:

- **Matrix Client-Server API** ([Documentación Oficial](https://spec.matrix.org/latest/client-server-api/)): Es la API estándar de Matrix. Se utiliza para acciones de gestión de salas como crear espacios, editar descripciones, modificar permisos o enviar mensajes a través del Bot de avisos.
- **Synapse Admin API** ([Documentación Oficial](https://matrix-org.github.io/synapse/latest/usage/administration/admin_api/index.html)): Es la API  del servidor Synapse desplegado en los servidores de la UGR. Nuestro panel la utiliza para ejecutar acciones con privilegios de administrador como crear cuentas de usuarios o forzar la matriculación saltándose las invitaciones.

### Estructura base de las peticiones

Para que el servidor de Matrix acepte y procese nuestras órdenes, todas las peticiones  definidas en este archivo comparten una estructura base: 

1. **Cabeceras de Autenticación (Headers):** Absolutamente toda petición debe ir firmada. Inyectamos el token de administrador en la cabecera con la siguiente estructura: `{"Authorization": f"Bearer {settings.MATRIX_TOKEN}"}`.
2. **Parámetros de Ruta (URL):** Definimos la URL hacia la que disparamos la petición.
3. **Cuerpo de la Petición (Payload JSON):** En operaciones POST o PUT, los datos de configuración (nombres de sala, descripciones, etc) se meten en diccionarios de Python y se envían convertidos en formato JSON.

Un ejemplo de petición dentro del código podría ser:

``` Python
headers = {"Authorization": f"Bearer {settings.MATRIX_TOKEN}"}

async with httpx.AsyncClient() as client:

	respuesta = await client.get(

		f"{settings.MATRIX_URL}/rooms/{room_id}/joined_members",
		headers=headers
	)
	
	if respuesta.status_code != 200: 
  
		return {"ERROR":f"Fallo al conectar con Matrix: {respuesta.status_code}"}
		
	datos_matrix = respuesta.json()
	
	return {
		"datos_sala": {
		
			"alias": sala.alias_principal if sala else "Desconocido", 
			"descripcion": sala.descripcion if sala else "Desconocido",
			"tipo": sala.tipo.value if sala else "Desconocido"
		},
		"miembros_matrix": datos_matrix.get("joined", {}) 
}
```

A continuación mostramos el listado de las funciones que se definen en este archivo:

### Funciones con peticiones:

**`obtener_info_sala()`**

- Recibe la sesión de la base de datos y el ID de una sala de Matrix. Consulta tanto la base de datos local como la API de Synapse y devuelve el nombre, descripción y listado de miembros de una sala.

**`obtener_perfil_usuario()`**

- Recibe el id de Matrix de un usuario. Lanza una petición para obtener el nombre del usuario en Matrix.

**`registrar_usuarios_matrix()`**

- Recibe la lista de alumnos desde Prado. Lanza una petición verificando si el usuario ya existe en Matrix, en caso de no existir le crea una cuenta automáticamente con una contraseña aleatoria provisional.

**`crear_espacio_asignatura()`**

- Recibe el nombre de la asignatura, su descripción y el ID del profesor. Genera un espacio en Matrix donde el profesor tiene permisos de administrador e inserta al resto de alumnos automáticamente.

**`insertar_alumnos_sala()`**

- Recibe el ID de una sala y la lista de ids de alumnos. Realiza una petición para insertar todos esos alumnos a la sala automáticamente saltándose la invitación manual.

**`arreglar_jerarquía()`**

- Recibe el ID del espacio raíz y el ID de la asignatura en Prado. Compara la jerarquía real del servidor Matrix con la que hay guardada en la bd local. Se encarga de actualizar los datos conforme a las incongruencias que encuentre mediante borrados, inserciones o actualizaciones de salas.

**`crear nodo()`**

- Recibe los datos de creación de una sala, su tipo y el ID del espacio padre. Crea un chat en Matrix introduciendo al profesor y al bot como administradores vinculando la sala al espacio raíz de la asignatura.

**`editar_nodo()`**

- Recibe el ID de una sala en Matrix y los nuevos datos de edición. Sobrescribe el nombre, la descripción o el  tipo realizando una petición a Matrix.

**`eliminar_nodo()`**

- Recibe el ID de una sala en Matrix. Expulsa todos los alumnos y profesor de la sala, para acabar borrandola.

**`accionar_celda_horario()`**

- Recibe el ID de la sala y un booleano para indicar si debe abrirse o cerrarse. Envía una petición Matrix para modificar el permiso de enviar mensajes en la sala, subiéndolo o bajándolo según lo especificado.

**`enviar_mensaje_bot()`**

- Recibe el ID de una sala en Matrix y el cuerpo del texto. Formatea el texto y envía una petición ara publicar en el chat el mensaje utilizando el token del Bot de Prado para que este envíe el mensaje.
